# A1: actions/checkout inputs, tested on v4, v5, v6 and v7

Run 2026-11-17 (run 44064719701) on GitHub-hosted `ubuntu-24.04`, in this public repository. Used by the reference post
"actions/checkout: every input and every major version, v4 to v7".

## What was run

One job per major version, using the floating tag (`actions/checkout@v4`, `@v5`, `@v6`, `@v7`) as a workflow that says `@v4` would.
The target repository is `actions/checkout` itself, pinned to the commit of its v7.0.1 tag
(`3d3c42e5aac5ba805825da76410c181273ba90b1`), because it has history, tags and a `src/` directory. Nine cases per version:
default; `fetch-depth` 0 and 2; `fetch-depth: 1` with `fetch-tags: true`, once with a SHA as `ref` and once with the default branch;
`sparse-checkout: src`; `sparse-checkout: README.md` with cone mode off; `filter: blob:none` with depth 0;
`persist-credentials: false`. After each, `scripts/observe.sh` reads what was left: the action's runtime from its `action.yml` on the runner, git version,
shallow or not, commits, tags, files on disk, the partial clone filter, how many `extraheader` and `includeIf` entries are in the repository's
git config, how many credential files are in the runner's temp directory, and whether the `commit` output equals HEAD.

`tag-points-at` rows record the commit each floating tag pointed at when the job ran (`git ls-remote`).

## Not run

SSH keys, LFS, submodules, a second private repository, `github-server-url`, GitHub Enterprise Server, and the refusal to check out a fork
pull request under `pull_request_target`. The reference post says which statements come from GitHub's text and which from this run.

## Limits

One repository, one run, one runner image (the image is in the A2 rows' `image` column and was `ubuntu24 20261111.x` that day), once per case. Counts
(commits, tags, files) are exact for that commit; they say nothing about repositories with other histories.
